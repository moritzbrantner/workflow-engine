Core model

Five objects, one explicit lifecycle.

The engine stays small by owning orchestration state and leaving node execution elsewhere.

01

Definition

A compiled workflow is registered immutably. A changed SHA-256 digest creates the next monotonic version.

workflowId + version + digest
02

Trigger

Manual, webhook, and five-field UTC cron triggers resolve either a pinned or latest definition.

manual | webhook | cron
03

Run

Every run permanently records the exact workflow version and digest that was selected for dispatch.

queued → running → terminal
04

Store

The MVP uses an in-memory store behind an explicit interface so persistence can replace it later.

definitions + triggers + runs
05

Dispatcher

A structural interface hands the pinned workflow to a runner without importing runner implementation code.

dispatch(request) → result

Architecture boundary

The engine orchestrates. The runner executes.

Immutable intent

A run cannot silently drift to a newer workflow definition after dispatch.

Replaceable infrastructure

Storage and dispatch are seams, not assumptions embedded into workflow documents.

Single responsibility

Scheduling and orchestration remain separate from node execution mechanics.
